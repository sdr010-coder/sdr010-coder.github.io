1. 全球 SAP S/4HANA 上线的 PMO 平台
阶段：企业交付
时间：2025 - 2026
身份：以 PMO 身份，在项目内部

问题：多国家、多工作流的 SAP 实施依赖 Excel 与会议治理，计划、风险、资源、预算与交付物缺少单一事实来源。
约束：已有商业 PPM 套件，但不承载本项目的分类字典、WBS/SOW 链与升级逻辑，且无法按项目所需速度调整。
我的角色：项目 PMO。负责流程模型、定义、数据设计、取舍与验收；以 AI 辅助开发完成，代码归属项目。
设计的机制：Programme - Workstream - SOW - WBS - Deliverable - RAID - Escalation - tracker 的数据链；455 条分类字典（L1 6、L2 61、L3 388）作为统一语言。
采用情况：被全球项目 PMO 使用，并作为亚太流程负责人 PMO readiness 培训的载体，覆盖十个国家。平台使 PMO 实践在上线前完成统一，而不只是事后报表；分类字典与数据模型承载了全球模板设计与本地化实践。
可验证指标：56 个业务页面、51 张数据表、11.9 万行代码、1485 条流程与 4759 条流程事实、4 个项目、53 条 WBS、24 个交付物、13 条 RAID（4 条升级）、48 行 SOW、44 位资源、25 场研讨会；4.5 个月从 0 上线。

2. 企业 Agent 平台 - 智能体治理
阶段：概念验证
时间：2026
身份：个人项目，设计与实现

问题：企业赋予 Agent 能力的速度，远快于其回答三个问题的能力：谁有权批准它、它能触碰什么、事后如何证明它做了什么。
约束：工作流引擎与 AI Copilot 或假设每步都有人员在场，或假设无需审批，两者都无法通过受监管流程的检验。
我的角色：负责流程模型、治理模型与可运行原型。
设计的机制：具名签署人授权（含转授权与职责分离）；6 道 fail-closed 门，绑定版本与参数摘要；双账本（业务事实账与哈希链鉴证账）与定期对账；批准、中止、审计作为一等操作。
成熟度：概念验证，两周完成；零场景进入生产。当时处于构建阶段而非发布阶段，该区分正是此设计的核心目的。
验证情况：与亚太流程负责人、ITBP 共同讨论并测试；随后向区域 IT VP 与全球 AI & Data VP 汇报，作为 AI 转型原型。因经高管评审，故明确标注成熟度。
可验证指标：475 条流程、8 步旅程、6 道门、双账本；26 个业务场景、6 个 Agent 工作流、191 条 EPM 流程、2073 个 BPMN Agent 单元、103 个人工角色。

3. Agentic 业务流程管理 - 端到端流程重构
阶段：概念验证
时间：2026
身份：个人项目

问题：AI 落地停滞于任务层，因为企业治理的对象是流程而非提示词；需要重构的单位是端到端流程，Agent 位于其中。
我的角色：将五条端到端流程族重构为以 Agent 为宿主的流程：Source-to-Settle、Plan-to-Make、Make-to-Stock、Order-to-Cash、Finance。
设计的机制：Agent 与流程的挂载点、人审点、Agent 注册与激活、知识与治理模块，使 Agent 成为可问责的流程参与者而非插件。
成熟度：概念验证，原型界面。
可验证指标：26 个场景、6 个工作流、103 个人工角色已完成建模。

4. Enterprise Harness - 公开的定义与参考实现
阶段：个人原型，已公开
时间：2026
身份：定义、11 篇文档与参考实现的作者

问题：行业普遍定义 Agent 是什么，但极少定义其产出凭什么被企业接受；该层缺少命名与参考实现。
设计的机制：Agent = 模型 + Harness，扩展为 Enterprise Harness = Harness + Mandate + Ledger；六道门阶梯；双账本与对账。
成熟度：已公开。83 个测试，Python 3.11+，无外部依赖，使规格可被证伪而非停留在描述。
